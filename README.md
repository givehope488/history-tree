# 历史事件树状图 · 中国现代史（2012 至今）

把历史事件画成**纵向树状图**：中国是中央主干，其他国家各自一条**同色分支**，
**同一时间发生的事件落在同一条水平线上**，纵向按**真实时间比例**排布。
每个事件就是一个独立节点，默认只显示极简概述，**点击节点展开详情**；
可以随时**添加 / 编辑 / 删除**节点，新节点会自动落到对应的时间层与分支上。

**支持多人同时在线协同编辑**：把带房间号的链接发给同学，大家在同一个房间里实时一起改，
改动按字段合并、不会互相覆盖，还能看到谁在线、谁正在编辑哪个节点。

内容骨架取自《中国近现代史纲要》(2023年版) **第十章 中国特色社会主义进入新时代**，
并把视野放大到世界（美国 / 俄罗斯 / 欧盟 / 世界 等分支）。当前是**框架 + 教材骨架**，
后续只需往 `src/data/seed.ts` 里继续补同期世界事件即可。

技术栈：**Vite + React 18 + TypeScript + Tailwind CSS**，无重型图表库，布局自实现；
协同用 **Yjs（CRDT）+ Liveblocks（托管后端）**。

## 布局规则（核心）

| 规则 | 实现位置 |
|---|---|
| 纵向 = 时间轴，按真实时间比例，且相邻时间层有最小行高 | `src/lib/layout.ts` 的「时间 → y」段，用 `toDayNumber`（真实天数）而非排序用的复合值 |
| 同一时间点的事件 y 相同（同一条水平线） | 每个事件按 `timeKey` 归并到同一层 |
| 同一国家的事件落在同一条彩色竖轨上 | 每个国家一条轨道，颜色取 `Country.color` |
| 中国 = 主分支（中央主干，最粗） | `Country.isMain` 决定 |
| 左右由 `order` 奇偶决定（奇数在右、偶数在左） | 新增分支不会把已有分支挤到另一侧 |
| **离主干多远由「该分支第一个事件的时间」决定：越早越靠近主干** | `lib/layout.ts` 的「轨道分配」段 |
| 分支第一次出现时用平滑曲线接到父分支上；只有主干允许向上延长 | `lib/layout.ts` 的「分支曲线接入」段 + `ramps` |

## 快速开始

```bash
npm install

npm run build      # tsc --noEmit 类型检查 + 产出 dist/
```

## 多人协同

### 它是怎么工作的

树状图的排布完全由 `{ 国家, 事件 }` 这两份数据推导出来（`lib/layout.ts` 是纯函数，
同样的数据必然画出同样的图），所以协同**只需要同步这两份数据**，
布局、节点、表单那些组件一行都不用改。

数据放在一个 **Yjs 共享文档**（CRDT）里，由 **Liveblocks** 托管同步，不需要自己跑服务器。

两个关键设计：

1. **每条记录在文档里是一个「字段表」，不是一整块对象。**
   Yjs 只在它自己的类型上做合并，普通对象是原子值——整块写入会把别人刚改的字段一起覆盖。
   做成字段表之后，张三改标题、李四改正文是两次独立的字段写入，**两边都能保住**。
2. **删除只打墓碑（`deletedAt`），不真删记录。**
   多人同时操作时，A 删掉某条、B 恰好正在编辑并保存，真删会让这条「复活」。
   所以删除只做标记，读取时过滤掉。

配套地，编辑表单在提交时只回写**自己实际改过的字段**（`EventForm.tsx` 的 `changedFields`），
表单的基准值在打开那一刻冻结，所以别人改了同一个节点不会影响你的判断。

3. **房间号记在浏览器里，另有本地快照兜底。**
   地址栏没带房间号时，回到上次用过的房间而不是随机开一个新的——否则重开页面就等于进了个空房间。
   同时本地留一份数据快照，负责三件事：连接中先铺图、房间被清空时恢复内容、给新房间当种子。
   快照只在「数据确实是房间里的真实内容」时才写（首次同步完成前不写），
   免得把缓存当成事实、把房间的快照写错。

   种子数据分三种情形，**绝不能把自己的内容灌进别人的房间**：
   快照就是这个房间的 → 用它恢复；是我自己点「新建房间」开出来的 → 用它继承；
   其他情况（比如别人分享了新房间的链接给我）→ 用课本骨架。

### 配置（只需要做一次）

1. 去 [liveblocks.io](https://liveblocks.io) 注册，在后台新建一个项目。
2. 复制 **public API key**（`pk_` 开头）。
3. 在项目根目录建 `.env.local`（已在 `.gitignore` 里，不会被提交）：

   ```
   VITE_LIVEBLOCKS_PUBLIC_KEY=pk_dev_xxxxxxxx
   ```

4. 重启 `npm run dev`。
**没有配 key 也能正常用**：应用会自动退化成单机模式，数据存在浏览器 localStorage，
页面照常打开、功能照常可用，只是不联网。

### 日常使用

- **长期保存**：你的板子绑定在一个**房间**上，浏览器会记住这个房间号，
  **下次打开应用会回到同一个房间**，改动都还在。地址栏里的 `#/b/xxxx` 就是这个房间。
- **邀请别人**：点顶栏 **「复制链接」**，把地址发给同学。谁打开这个链接就在同一个房间里。
  （换电脑、换浏览器、或者清了浏览器数据之后，都要靠这个链接回到自己的板子。）
- **新建房间**：点顶栏「在线 N」→「新建房间（复制当前内容）」。
  会开一个新房间并**把当前这块板子复制过去**（原房间保留，用原链接还能回去）。
  适合给另一个班开一块同样的板子。
- **昵称**：首次进入会问一次，只存在你自己的浏览器里。想改：点顶栏「在线 N」→「改我的昵称…」。
- **看谁在**：点顶栏「在线 N」展开成员列表，能看到每个人和「正在编辑」标记。
- **清空口令**：点顶栏「在线 N」→「设置清空口令…」。设了之后，
  「恢复初始数据」和「导入 JSON 覆盖」都要先输口令。
- **备份**：顶栏「数据 → 导出 JSON」。协同时建议定期导出，这是唯一的完整备份手段。

### 数据存在哪、丢了怎么找

| 存哪 | 内容 | 说明 |
|---|---|---|
| Liveblocks 房间 | 权威数据 | 同房间所有人共享，这是真正的「长期保存」 |
| 浏览器 localStorage | 房间号 + 一份快照 | 记住「上次在哪个房间」；连接中/断网时先用快照把图铺出来；**房间万一被清空了，也靠它恢复** |

所以：**改动跟着房间走**，不跟着浏览器走。只要房间号还在（链接没丢），换台电脑打开同一个链接就能看到全部内容。

**本地快照的三条用途**（都只在必要时才起作用）：

1. **连接期间先铺图**：首次同步完成前先用快照显示内容，不会先看到一片空白。
2. **房间被清空时恢复**：如果连上后发现房间是空的、而本地正好有这个房间的快照，
   就**用快照把内容恢复回来**，而不是给你一份课本骨架。
3. **新建房间时继承**：点「新建房间」开出来的新房间，用快照当种子，继承当前内容。

反过来说，**如果链接和浏览器数据同时丢了，内容就找不回来了** —— 所以定期导出 JSON 备份很重要。

### 关于安全，几句实话

- **`pk_` 开头的 public key 放在前端是安全的**，它本来就是设计成公开的。
  **`sk_` 开头的 secret key 绝对不能放进前端代码**，那是后台用的，泄露等于把项目交出去。
- **房间号是长随机串**（地址栏 `#/b/xxxx`），因为匿名链接人人可改，短号会被人猜中闯进来。
  不要把房间号发到公开的地方。
- **清空口令只是防手滑，不是真安全。** 校验在前端做，懂技术的人绕得过去。
  别用它保护重要内容，重要内容请随时导出 JSON 备份。
- 匿名链接意味着**拿到链接的人都能改**，没有权限分级。适合班级内协作，不适合放敏感内容。

## 怎么用（功能说明）

1. **点击任意节点胶囊** → 在该节点旁展开详情卡（Markdown 正文、相关链接、标签）。
   再点一次或点卡片右上角「收起」即可折叠。
2. 顶栏 **「＋ 添加分支」** → 新建一条国家分支：填名称、选主干左侧/右侧、选颜色。
   保存后会直接打开「添加节点」表单并预选这条新分支 —— 因为**没有事件的分支不会画在图上**，
   给它加上第一个事件，分支就会带着曲线出现在树状图里。
   （还没有事件的分支会列在图例下方，方便回头补事件。）
   想删掉某条分支，点图例里它名字后面的 **✕** 即可：会二次确认，并说明会连带删掉多少个事件节点；
   主干「中国」不可删除。
3. 顶栏 **「＋ 添加节点」** → 填时间（必填）、国家（必填，决定落在哪条分支）、
   事件概述（必填）、详情（Markdown）。保存后自动落到对应时间层与分支，并展开详情。
   国家选择器里也能直接「＋ 新建国家分支」。
4. 详情卡右下角 **「编辑 / 删除」**：
   - 编辑：改时间或国家后，节点会**重新归位**到新的时间层与分支。
   - 删除：二次确认后从图中移除。
5. 顶栏 **「数据」**：导出 JSON / 导入 JSON（覆盖当前数据，带二次确认）/ 恢复初始数据。
6. 图例里点 **「收起全部详情」** 可以一次性折叠所有展开的卡片。

## 数据与规则要点

- **节点 = 事件**：没有单独的「时间点」实体，时间层由事件的 `time` 派生（`timeKey` 相同即同一层）。
- **每个事件用自己真实的日期**：不要把一个教材小节里的几个事件都写成同一天，否则它们会被压在同一条水平线上、
  看不出先后。`seed.ts` 里每条事件都标了它实际发生（或该动态最标志性）的日期。
- **纵向比例用真实天数**：`time.ts` 的 `toDayNumber()`（days_from_civil）把日期换成距 1970 的天数，
  再把「平均间隔」映射到 `comfortableGap`，所以总高约等于 `(时间层数-1) × comfortableGap`，
  不会因为某两件事相隔很久就把整张图拉成几万像素。**不要用 `toSortable` 做排布** ——
  它是 `year*10000+month*100+day` 的复合数，1 天和 1 个月在上面差 100 倍。
- **分支接入**：每条分支第一次出现时，会从父分支上以一段三次贝塞尔曲线长出来，而不是凭空出现一条平行线。
  选取规则是**由内向外找**，并且**不允许把非主干分支向上延长**：
  - 只有「当时已经存在」（轨道本来就覆盖到曲线起点）的内侧分支才能当父分支；
  - 内侧分支还没出现时继续往中间找；
  - 主干贯穿整条时间轴，是最终兜底，也**只有主干**允许向上延长。
  例如 欧盟 接到 美国（2015 时 美国 已存在，轨道本来就够长）；而 世界 接到主干（2012 时 俄罗斯 还没出现，
  若接到 俄罗斯 就得把它的轨道向上拉，所以继续往中间落到主干）。曲线两端竖直相切，和竖直轨道自然衔接；
  跨度按离主干的水平距离自适应（越靠外越舒展）。
- **加 / 删国家分支**：顶栏「＋ 添加分支」或表单里的国家选择器都能新建。
  `order` 的奇偶决定左右（奇数右、偶数左），颜色可选，缺省从调色板里轮取。
  **离主干多远按「该分支第一个事件的时间」排：越早越靠近主干**——所以给一条分支加上第一个事件时，
  它可能插到内侧、把已有分支往外挤一格，这是规则本身要求的（不是 bug）。
  删除走图例里的 **✕**：会连带删除该分支上的所有事件节点（二次确认里会写明条数），
  主干（`isMain`）在 store 里被硬性拦住，删不掉。
- **归位**：添加或编辑时不需要额外代码——节点位置完全由 `computeTreeLayout(events, countries)` 派生，
  时间或国家一变，布局（含曲线接入）自动重算。
- **时间**：`'2012-11-08' / '2012-11' / '2012' / '2012年11月8日' / '-500' / '公元前500'` 都能解析；
  排序键为 `year*10000 + month*100 + day`，负年份天然排在公元之前。
- **持久化**：
  - 协同模式：数据在 Liveblocks 托管的共享文档里，刷新不丢，同房间的人实时可见。
  - 单机模式：写入 localStorage（键 `ch10-history-tree:v3`），刷新不丢。
  - 导入的任意 JSON 都会先经过 `sanitizeData` 清洗，非法条目丢弃、缺字段补默认值。

## 单机演示版（可选）

`demo-standalone.html` 是**单文件、单机**版本：双击就能在浏览器里打开完整应用，
数据写本机 localStorage，**不联网、不协同**（用于没装 Node 或没网时演示）。

```bash
npm run build:standalone      # → demo-standalone.html
```

这条命令用 `--mode standalone` 构建，会加载 `.env.standalone` 把 Liveblocks key **置空**，
所以单文件里不含任何 key、也不会尝试联网。构建脚本还会检查产物里有没有残留 key，
有就直接报错退出，避免不小心把联网版当成单机版发出去。

（`npm run build` 产出的 `dist/` 是**联网协同版**；两者会互相覆盖 `dist/`，
所以想让 `dist/` 是协同版，最后再跑一次 `npm run build`。）

## 换章节 / 换主题 / 补数据

只需要改 `src/data/seed.ts`：

- 加事件：往 `seedEvents` 里追加 `{ id, title, countryId, detail, time }` 即可，排序与归位自动完成。
- 加国家分支：往 `seedCountries` 追加 `{ id, name, color, order }`，`order` 决定它在主干哪一侧、离主干多远。
- 种子数据**只在房间/浏览器还是空的时候写入一次**（靠共享文档里的 `meta.seeded` 标记）。
  已有数据的房间不会因为改了种子而变样；要重置请用顶栏「数据 → 恢复初始数据」。

## 已知边界

- 详情 Markdown 只支持标题、列表、加粗、斜体、行内代码、链接、引用、分隔线；**不支持图片**。
- 链接仅允许 `http/https/mailto`，其余协议按纯文本渲染，避免注入。
- 分支较多时图形会横向滚动（轨道宽度固定，不会压缩到看不清）。
- 纵向按真实时间比例，因此时间跨度大的两个节点之间会留出较大空白（这是「比例」的代价）。
- 协同是**整字段覆盖**：两个人同时改**同一个字段**（比如都改标题），后保存的会赢，
  不会有字符级合并。改**不同字段**（一个改标题、一个改正文）则两边都保住。
- 匿名链接没有权限分级，拿到链接的人都能改。
- **改动跟着房间走，不跟着浏览器走**。链接和浏览器数据同时丢失就找不回来了，请定期导出 JSON 备份。
- 本地快照只是「连接期间的占位」「房间被清空时的恢复源」「新房间的种子」，
  **不是完整备份**；真正的数据在房间（服务器）里。
- 快照是**整块覆盖**的，只保留最近一份，没有历史版本。
- 开发模式下可以在控制台用 `window.__collab` 查看共享文档和同步状态（`__collab.doc` / `__collab.provider`）。
